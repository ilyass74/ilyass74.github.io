THE ENGINEERING QUESTION

Separate order value, collected cash and delivery performance.

Retail reporting becomes misleading when order value, cash collections and delivery status are blended. This batch lakehouse models them separately, carrying source identity through Bronze, Silver and Gold.

From a consistent snapshot to typed Delta tables

The Python exporter reads a consistent PostgreSQL snapshot. Bronze records the source file and ingestion time and avoids re-appending an unchanged batch. Silver validates required values, typed fields, primary keys and foreign-key relationships across all six entities. Delta MERGE inserts new keys and updates only when source updated_at is newer. The Databricks job sequences ingestion, validation and Gold processing.

Make the business semantics visible

Gold calculates non-cancelled order value separately from completed payments and refunds. Delivery on-time rate uses completed deliveries as its denominator. SQL assertions reconcile order value, net cash and delivery counts against Silver. Power BI reads downloaded Gold snapshots; the four included report screenshots show filtered synthetic data, not a client deployment or real sales.
