THE ENGINEERING QUESTION

What should we measure to detect a leak?

Water loss is a physical problem observed through incomplete measurements. AQUA NEXUS (formerly AQUA Sentinel) explores the relationship between hydraulic modeling, sensor placement, leak detection and operational decisions. The entire system is a prototype on simulated infrastructure. AQUA NEXUS is the owner-selected display name; the existing aqua-sentinel repository, original experiment names and historical documentation remain unchanged.

Start with a physical model

The initial WNTR implementation constructs a reservoir, junctions and pipes, splits a pipe to create a leak location and runs WNTRSimulator. Pressure and flow outputs feed scenario datasets. The project retains distinct versions of simulation, detection and operations rather than silently treating all experiments as one network. The historical R–A–B–C–D network, P2–P5 sectors and the later A/B valve laboratory do not have an invented one-to-one correspondence.

Separate model development from evaluation

The ML V2 training record describes 80 simulated day-scenarios split into 48 training, 16 validation and 16 original test scenarios, with no scenario overlap. Candidate Random Forest and histogram gradient-boosting configurations are selected using validation. The selected V2 record is a Random Forest with depth 14 and minimum leaf size 8. Source and dataset hashes preserve the experiment lineage. A separate 64-scenario test compares frozen V1 and V2 models; labels are not sensor input.

Recall has a cost

On the same new 64-scenario simulated test, V1 detected 13 of 32 leak events with five false alerts. V2 detected 31 of 32, with ten false alerts and only 15 of the 32 leaks detected within five minutes. Its median delay among detected events was 360 seconds. This makes the improvement and the tradeoff visible together. Event recall and minute-level precision measure different things and are never substituted for each other.

Sometimes better sensing matters more than a more complex model

A sensor study preserves the original nine measurements — four pressures and five flows — and adds four virtual downstream flow meters. For P2–P5, upstream minus downstream flow becomes a local physical balance. The calibration uses healthy training windows and causal smoothing, with confirmation before opening an alert. The important assumption is that there is no legitimate withdrawal or storage between the two synchronized meters. Otherwise a balance alone cannot distinguish consumption from leakage.

Implementation & evidenceaqua_etude_capteurs_v1.py

Test the selected physical balance independently

A subsequent held-out 64-day simulated test contains 32 leak events and 13 installed virtual sensors. Bilans_13 detected and localized all 32 within five minutes; median delay was 180 seconds and the report counts zero false-alert episodes. The same report still records 163 alert-minutes outside leak periods, so zero false-alert episodes does not mean zero out-of-leak alert time. Localization uses paired physical balance at first triggering, not an ML localization model. Sensor drift, failures, clock offsets and field uncertainty are outside this idealized test.

Risk and operations are separate engineering questions

The risk experiment uses logistic regression to prioritize a fixed 20% inspection quota on a synthetic cohort of 2,000 assets. It is not a forecast of real pipe failure. The V3 application adds sensor state, interventions, reports, an evidence-grounded assistant and approval-gated valve experiments. Commands can be refused for poor quality or communications, and faulty feedback freezes movement. The assistant may explain a simulated action but does not execute it. The valve model is quasi-static and does not establish real transient safety.

WHAT THIS WORK ESTABLISHES

Scope & limitations

  • Every result is simulated; no field deployment or real equipment validation.
  • The idealized paired-meter test excludes drift, failures, timing offsets and legitimate withdrawals between meters.
  • V2 ML and the later physical-balance detector use different experiments; their results are not pooled.
  • The V3 operational layer adds no newly proven real-world ML detection rate.
