THE ENGINEERING QUESTION

Idempotent application of delivered CDC events.

A live-looking dashboard is only useful if replayed events do not silently double its totals. This local CDC system focuses on the transaction boundary between source changes, reporting state and committed offsets.

Apply before acknowledging

The consumer stores a unique topic/partition/offset ledger entry and the corresponding row update in one PostgreSQL transaction. Kafka acknowledgment follows the database commit. Redelivery of the same offset is skipped. The source simulator cancels an order and restores stock transactionally; monetary storage uses integer centimes. Only the shop schema is captured, avoiding a feedback loop from analytics writes.

Be explicit about consistency

Delivery is at least once with idempotent application of the same Kafka position, not an end-to-end exactly-once guarantee. Changes across source tables can appear partially while reporting catches up. Six event-decoder unit tests and a source/reporting comparison script are included; the latter must run after source writes stop. A three-second dashboard refresh is not a measured pipeline latency.
