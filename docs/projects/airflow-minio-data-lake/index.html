THE ENGINEERING QUESTION

Move a local order ETL into scheduled object-storage processing.

Separating orchestration from transformation makes a local ETL easier to operate. This project extends order processing with a storage sensor, task dependencies and S3-compatible reads and writes.

Schedule, wait, transform and query

The hourly DAG uses a PythonSensor every 60 seconds, with a one-hour timeout, then a Bash task runs the Python ETL. Boto3 reads orders.csv, pandas derives year_month and PyArrow writes one Parquet object. DuckDB reads that object over its S3/httpfs path and groups order counts and amounts by status. Adding a month column does not physically partition this object-storage output.

The operational edges matter

The sensor checks only the first ten objects for any CSV, while the ETL always reads orders.csv. Existing input can be processed again and the output key is overwritten. MinIO is external to the supplied Compose stack. A legacy BashOperator import may need adaptation for the installed Airflow provider. These are source-inspected constraints, not fixed or newly validated features.
