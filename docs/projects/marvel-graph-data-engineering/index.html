THE ENGINEERING QUESTION

Turn unstructured dialogue into a queryable graph — and expose the heuristic.

A graph is only as meaningful as the rule used to create its edges. This pipeline explores the transformation of screenplay text into relationships while keeping inferred co-occurrence distinct from verified character interaction.

Make the edge construction inspectable

The parser detects uppercase speaker labels and accumulates character pairs within a five-entry dialogue window. It writes interaction rows to Parquet. The Neo4j loader merges character nodes and movie-specific relationships, incrementing weights on repeated loads. Streamlit queries the graph and renders a NetworkX/Plotly view. This demonstrates text-to-graph modeling and graph serving, not semantic relationship extraction.

Keep fallback data visibly synthetic

When scripts cannot be parsed, the fallback connects every unique character pair with weight one. That is demonstration data, not a recovered film graph. Case-sensitive aliases and a non-idempotent loader limit interpretation; rerunning the same file increases existing weights. There is no automated accuracy or performance benchmark.

Scope & limitations

  • Co-occurrence does not prove conversation or a canonical relationship.
  • Fallback ignores film boundaries; repeated graph loading inflates weights.
  • External pages and screenplay format remain dependencies.
